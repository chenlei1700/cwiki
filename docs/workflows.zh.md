# 实战流程 —— 分场景的查找与更新

> 中文（默认） | [English](workflows.md) — 如有出入以英文版为准。

规则书（[SCHEMA](../templates/SCHEMA.md)）说的是"什么合法"；本文说的是"实际怎么走"。每个场景给四样东西：**你说什么 → LLM 走哪几步 → 动了哪些文件 → ⭐ 独有能力在哪一步起作用**（⭐ 标注的步骤是 star 更多的通用工具里没有的——对比见 [README「为什么是 cwiki」](../README.md#为什么是-cwiki)）。

## 查找类

### Q1 查历史结论

**你说**：`之前对 X 的结论是?` / `wiki 里有没有 X`

1. LLM **先读 `wiki/index.md`**（永远从索引入手，不凭记忆直奔某页——索引是页面位置的权威）。
2. 读 2–4 个候选页全文（不是只扫标题）。
3. 带引用作答：*"据 [[concepts/xxx]] §2 与 [[experiments/yyy_20260520]]……"*。
4. ⭐ 若答案 load-bearing 依赖某个产物，页面 frontmatter 的 `sources:` 指纹（SCHEMA §15.1）告诉你该证据**今天是否仍然成立**——夜检对每条 source 报 在/已变/不在 三态。一个"结论还在、证据已变"的页面会被点名，而不是被当成现行真理引用。
5. 回答若产出新洞见，LLM 提议 ingest（不擅自写入）。

### Q2 查当前状态

**你说**：`现在 ship 的是哪一版?` / `当前配置是什么?`

1. ⭐ **先找 L2 派生视图**（`_current_*` 文件）——它存在的唯一目的就是回答这个问题，且由同步脚本每夜从 L1 账本重生成，手改不进去。
2. 没有派生视图时，按 ⭐ **固定的"判最新"排序**（SCHEMA §15.3）裁决，不凭感觉：文件名语义（`_current_*` vs 带日期的历史页）→ 墓碑/supersedes 声明 → 最后手段 `git log -1`。**永远不用 mtime**（同步脚本和 checkout 会无意义地重写它）。
3. 问的是代码现状（"函数 X 现在干什么"）→ 读代码，wiki 只提供"为什么"和历史。发现 wiki 与代码漂移 → 点出来并提议更新 wiki。

### Q3 按话题拉全貌

**你说**：`X 这个话题现在什么情况?`（需已启用话题层，SCHEMA §16）

1. 在 `wiki/_topics.json` 里 resolve 话题名/别名。
2. ⭐ **五栏视图现场派生**（不存储，存了就是会漂移的第二份拷贝）：① 内容页在哪 ② 当前进度（沿 anchors 读账本/派生视图）③ 变更历史（log 条目按话题关键词聚合）④ 相关会话 ⑤ 相关代码根。
3. 这正是"提到一个话题就能定位到内容、进度、历史、关联会话、关联代码"的那个入口——没有话题层时这个答案抹在十个地方。

### Q4 探索前查重

**你说**：`我想试试 Y 方向`（任何探索型工作的第一步）

1. ⭐ **先查假设账本**（`hypothesis_history.jsonl`，Mechanism 2）：同主题的历史行里有没有 `fail`？失败**原因**是什么——"量不出来而关"与"没效果而关"导向相反的决策，账本里两者是分开记录的。
2. ⭐ 方向级的关闭是结构化 `action: close` 记录——所以"没查到记录"真的意味着没试过，而不是"试过但结论写在某段散文里工具看不见"。
3. 查完才开工；收尾回到 [U2](#u2-实验收尾落档)。这是全系统投入产出比最高的一个习惯。

## 更新类

### U1 喂新材料（ingest）

**你说**：`ingest this: <材料>` / `把这个加进 wiki`

1. 分类（concept / experiment / source / architecture / 领域目录），不确定就问一次。
2. 定位或新建宿主页——已有同主题页默认**追加**；自成一体的带日期事件、或页面超 ~300 行、或新概念将被多页引用时才新建。
3. ⭐ 新建页先过 **preflight 查重**（标题近似检索已有页名），frontmatter 记 `similar_checked:`——防近重复页慢性积累。
4. 加 `[[交叉引用]]`，且**双向**：A 页加了 `[[X]]`，X 页必须补回链。
5. `index.md` 加条目 + `log.md` 顶部加一行（带类别词）。
6. 结论是初步的就写 `Status: tentative`——过期 60 天的 tentative 会被 lint 点名。

### U2 实验收尾落档

**做完一次实验/处理完一次事故**：

1. 建 `experiments/<主题>_YYYYMMDD.md`（冻结的历史事件，永带日期），一行结论放最顶。
2. ⭐ frontmatter 写 `sources:` 指纹钉住 load-bearing 产物（结果 JSON 的 sha256 / 代码态 commit——两档不混用）。
3. ⭐ 假设账本**追加**一行：假设、改了什么、结果、失败原因、教训链接。**输掉的实验同样入账**——这是 Q4 查重有答案的前提。
4. 牵连的 concepts 页更新（走交叉引用图），log 一行。

### U3 新证据与既有结论矛盾

**发现**：新数据/新实验与某页现有结论打架。

1. ⭐ **不改正文**。先把矛盾落进该页的「待确认/矛盾点」区，带**双方**证据指针（SCHEMA §14）。
2. 裁决（人决定，或更多证据到来）之后才改正文；已裁决的矛盾条目移入「演变轨迹」。
3. ⭐ 合并两个冲突结论时**两说并存**、显式写明分歧——"后写的赢"被明令禁止，因为它销毁"曾有分歧"这条信息本身。

### U4 订正错误结论

**发现**：某页（或账本某行）的结论是错的。

1. 页面：改正文 + 「演变轨迹」加一行 + ⭐ 回到**原文位置**加 `⛔已订正→见[日期]` 标记——未来读到旧段落的人当场知道它作废，而不是读完才在别处发现。
2. 账本行：⭐ **永不原地改**——追加替代行，或写 overlay 记录（带 `invalidated_by` 与原因）。N 个工具在读账本，原地改会把它们全部静默去同步。
3. 订正影响到 CLAUDE.md 里的教训条目 → 一并更新那行指针。

### U5 发布类多文件事件

**要做**：发版/上线/换配置——那种"同一类事件每次都要动同一批文件、总漏一步"的事。

1. 打开 `MAINTENANCE_ROUTING.md` 找到该事件行，按**编号 checklist 严格顺序**走。
2. ⭐ 表的每行带两个别处没有的列：**漏做症状**（把表变成反向诊断索引——出怪事时按症状反查漏了哪步）与**兜底闸**（哪个自动检查会接住漏做——以及哪些行没有网，要格外小心）。
3. 事件末尾必有一步：**重启长活进程**——"配置了 ≠ 生效了"，worker/server 在启动时锁定配置。
4. 次日核验步确认变更真的活了；release 账本追加一行。

### U6 往 CLAUDE.md 记教训

**会话结束想留一条**：

1. 教训的**事实**写进 wiki（experiments 页或 concepts 页——T1/T2 档位）。
2. CLAUDE.md 只加**一行 + 指针**：`- [日期] 一句话结论 → 原文: [链接]`。
3. ⭐ 写长了会被抓：**单条形态闸**（SCHEMA §13.4）次日点名超过 ~800B、或 >500B 无链接的新条目——一条归错档的 3KB 战记不用等总预算爆线才暴露。
4. 总量逼近预算线 → 触发[蒸馏 SOP](maintenance-mechanisms.zh.md#mechanism-7--蒸馏回路上下文预算)（交互执行，含抽查比读人工关）。

### U7 页面取代与删除

**要做**：新页取代旧页，或某页该删了。

1. 取代：新页 frontmatter 声明 `supersedes: [旧页路径]`；⭐ 旧页顶部**必须**加墓碑横幅 `> **已废弃** → 见 [[新页]]`——声明了却没立碑，夜检红灯。
2. 删除：路径登记进 `wiki/_tombstones.json`（日期、原因、后继页）。
3. ⭐ **复活检测**：哪个生成器不知道墓碑、把死页又吐出来了——夜检第二天抓到。注册表对没接它的生成器也有牙，这是"墓碑是检测型执法"的含义。
4. 别的页里指向旧页的 `[[链接]]` 顺手改向后继页。

### U8 夜检红灯处置

**夜间 lint / 漂移检测 exit 1 了**：

1. ⭐ 报告是**证据不是布尔**：每条违规带哪个文件、什么问题、修复动作——按行处理，不存在"3 violations 然后不知道干嘛"。
2. 修完重跑该检查确认转绿。
3. ⭐ 若红灯原因是**检查自己错了**（误报）：改判据后必须跑它的 `--selftest`，并给新的失败模式**补一例故障注入**——守门员也要被守，改坏判据的人应得到红色测试而不是安静的绿夜。
4. 某条违规决定不修（接受现状）→ log 里记一行决定与理由，别让它每晚刷屏训练人忽略报告。
